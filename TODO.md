## Gotcha for future engine code
- The Vite template's `tsconfig` sets `erasableSyntaxOnly`, which forbids TypeScript constructor parameter-property shorthand (`constructor(private readonly x: T)`) and other non-erasable syntax (e.g. `enum`). Declare fields and assign them in the constructor body instead.

## Gotcha for future UI code
- Don't lazily initialize a ref's value by checking/assigning `ref.current` directly in the render body (`if (ref.current === null) ref.current = ...`) — oxlint's React rules flag this (`Cannot access refs during render`), and it can genuinely cause stale reads. Use `useState(() => ...)`'s lazy initializer for "create once" values instead (this has come up twice now — `Simulation` in `Level1Page`, `PnlTracker` in `Level3Page`). Keep `setState` calls inside event handlers/callbacks, never in the render body itself.
- A file that runs inside a Web Worker's own global scope (uses `self`/`postMessage` directly) needs the `WebWorker` lib and must be excluded from the main app's `DOM`-lib project; a file that merely *constructs* a `Worker` (like `workerClient.ts`) runs on the main thread and needs the opposite — `DOM`, not `WebWorker`. Don't lump "everything under `src/worker/`" into one tsconfig without checking which side of the `postMessage` boundary each file actually executes on.
